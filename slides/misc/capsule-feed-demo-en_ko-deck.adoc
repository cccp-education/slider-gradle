== 소개

[%step]
* 슬라이더 → 캡슐 파이프라인 시연
* 스피커 노트에서 캡슐 스크립트 생성
* 캡슐-gradle에 의해 사용되는 평문 계약

[NOTE.speaker]
--
이 캡슐 피드 파이프라인 시연에 오신 것을 환영합니다.
우리는 slider-gradle가 AsciiDoc 데크에서 스피커 노트를 추출하고 이를 capsule-gradle에서 사용되는 스크립트로 만드는 과정을 살펴볼 것입니다.
--

[.slide,data-transition="slide"]
== capsule-gradle 계약

[%step]
* 구분자 기반 평문 형식
* 헤더: `=== CAPSULE SCRIPT : name ===`
* 슬라이드당 하나의 세그먼트: `--- SLIDE n : title ---`
* 본문: 스피커 노트를 그대로 사용

[NOTE.speaker]
--
슬라이더와 캡슐 간의 계약은 의도적으로 단순합니다: 헤더와 슬라이드당 하나의 세그먼트가 포함된 텍스트 파일입니다. 각 세그먼트는 TTS 나레이션이 되는 스피커 노트를 담고 있습니다.
--

[.slide,data-transition="slide"]
== 라운드 트립 검증

[%step]
* 파서가 AsciiDoc에서 세그먼트를 추출합니다
* 라이터가 이를 평문 계약으로 직렬화합니다
* capsule-gradle가 동일한 형식을 다시 파싱합니다
* 손실 없음: 슬라이더가 쓴 것을 캡슐이 읽습니다

[NOTE.speaker]
--
라운드 트립이 검증됩니다: 파서는 AsciiDoc 소스에서 세그먼트를 추출하고, 라이터는 이를 평문 계약으로 다시 직렬화하며, capsule-gradle는 정확히 동일한 형식을 손실 없이 다시 파싱합니다.
--

[.slide,data-transition="slide"]
== 결론

[%step]
* 캡슐 피드 = 스피커 노트 추출
* 계약에 JSON도, 스크린샷도 없습니다
* 스크린샷은 capsule-gradle에 의해 실시간으로 촬영됩니다
* 슬라이더가 스크립트를 생성하고, 캡슐이 이를 소비합니다

[NOTE.speaker]
--
마무리하자면: 캡슐 피드는 단순히 스피커 노트를 추출하는 과정입니다. 계약에 JSON도 스크린샷도 없습니다 — 스크린샷은 비디오 생성 중에 capsule-gradle에 의해 실시간으로 촬영됩니다. 슬라이더가 스크립트를 생성하고, 캡슐이 이를 소비합니다. 명확한 생산자-소비자 경계가 유지됩니다.
--
