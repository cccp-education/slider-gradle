== Введение

[%step]
* Демонстрация конвейера slider -> capsule
* Генерация скрипта capsule из заметок ораторов
* Текстовый контракт, потребляемый capsule-gradle

[NOTE.speaker]
--
Добро пожаловать на эту демонстрацию конвейера capsule feed.
Мы посмотрим, как slider-gradle извлекает заметки оратора из колоды AsciiDoc,
чтобы создать скрипт, потребляемый capsule-gradle.
--

[.slide,data-transition="slide"]
== Контракт capsule-gradle

[%step]
* Текстовый формат с разделителями
* Заголовок: `=== CAPSULE SCRIPT : nom ===`
* Сегмент на каждый слайд: `--- SLIDE n : titre ---`
* Тело: заметка оратора как есть

[NOTE.speaker]
--
Контракт между slider и capsule намеренно прост:
текстовый файл с заголовком и сегментом для каждого слайда.
Каждый сегмент содержит заметку оратора, которая станет озвучкой TTS.
--

[.slide,data-transition="slide"]
== Проверка round-trip

[%step]
* Парсер извлекает сегменты из AsciiDoc
* Записыватель сериализует в текстовый контракт
* Capsule-gradle повторно парсит тот же формат
* Нулевые потери: то, что пишет slider, читает capsule

[NOTE.speaker]
--
Round-trip валиден: парсер извлекает сегменты из исходного AsciiDoc,
записыватель сериализует их в текстовый контракт,
и capsule-gradle повторно парсит тот же формат без какой-либо потери данных.
--

[.slide,data-transition="slide"]
== Заключение

[%step]
* Capsule feed = извлечение заметок оратора
* Нет JSON, нет скриншотов в контракте
* Скриншоты делаются в реальном времени capsule-gradle
* Slider создает скрипт, capsule его потребляет

[NOTE.speaker]
--
В заключение: capsule feed — это просто извлечение заметок оратора.
Нет JSON, нет скриншотов в контракте — скриншоты делаются в реальном времени
capsule-gradle во время генерации видео. Slider создает скрипт,
capsule его потребляет. Чистая граница между производителем и потребителем.
