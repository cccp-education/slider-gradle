== 소개

[%step]
* 슬라이더에서 캡슐로 파이프라인 표시
* 발표자의 메모에서 캡슐 텍스트 생성
* 캡슐-그레이들에서 소비되는 일반 텍스트 계약

[NOTE.speaker]
--
캡슐 피드 파이프라인 데모에 오신 것을 환영합니다.
슬라이더-그레이들이 AsciiDoc 프레젠테이션에서 발표자 메모를 추출하는 방식을 확인합니다.
캡슐-그레이들이 소비할 텍스트를 생성합니다.
--

[.slide,data-transition="slide"]
== 캡슐-그레이들 계약

[%step]
* 정해진 일반 텍스트 형식
* 헤더: `=== CAPSULE SCRIPT : name ===`
* 각 슬라이드당 하나의 섹션: `--- SLIDE n : title ---`
* 본문: 발표자 메모 그대로

[NOTE.speaker]
--
슬라이더와 캡슐 간의 계약은 의도적으로 간단합니다:
각 슬라이드에 헤더와 하나의 섹션이 있는 텍스트 파일.
각 섹션은 내레이터 메모를 포함하며, 이는 음성 내레이션이 됩니다.
--

[.slide,data-transition="slide"]
== 왕복 검증

[%step]
* 파서가 AsciiDoc에서 섹션을 추출합니다.
* 작성자가 일반 텍스트 계약으로 직렬화합니다.
* 캡슐-그레이들이 동일한 포맷을 다시 파싱합니다.
* 손실 0: 슬라이더가 쓴 것을 캡슐이 그대로 읽습니다.

[NOTE.speaker]
--
왕복 검증을 완료했습니다: 파서가 AsciiDoc 원본에서 섹션을 추출합니다.
작성자가 이를 다시 일반 텍스트 계약으로 직렬화합니다.
그리고 캡슐-그레이들이 정확히 동일한 포맷을 다시 파싱하여 데이터 손실이 없습니다.
--

[.slide,data-transition="slide"]
== 결론

[%step]
* 캡슐 피드 = 발표자 메모 추출
* 계약에 JSON이나 스크린샷이 없습니다.
* 스크린샷은 캡슐-그레이들에 의해 직접 캡처됩니다.
* 슬라이더가 텍스트를 생성하고 캡슐이 소비합니다.

[NOTE.speaker]
--
마무리하자면: 캡슐 피드는 단순히 발표자 메모를 추출하는 것입니다.
계약에 JSON이나 스크린샷이 없으며 — 스크린샷은 캡슐-그레이들에 의해 비디오 생성 중에 직접 캡처됩니다. 슬라이더가 텍스트를 생성하고 캡슐이 이를 소비합니다. 생산자와 소비자 사이에 명확한 경계가 있습니다.
--
