== EPIC SLD-5 — Detail US

_Vision_ : Pipeline de traduction de deck one-to-many. Partant d'un deck source
(deck-context.yml + .adoc) dans une langue, génère les 10 variantes localisées
couvrant le top 10 des langues les plus parlées (source : `10 langues les plus
parlés.csv` — aligné sur `LanguageCatalog.supportedCodes()` : en, zh, hi, es, fr,
ar, bn, pt, ru, ur).

_Problématique_ : Aujourd'hui slider sait générer un deck dans UNE langue
(`proposeDeckContext -Planguage=X`) et traduire du texte libre entre 10 langues
(`translate{From}To{To}`). Il ne sait PAS prendre un deck existant et produire
ses 10 variantes localisées. SLD-5 comble ce manque — c'est le chaînon manquant
du story i18n entamé en SLD-3.

_Domaine DDD_ : `slider.translation` (nouveau) — value objects purs
(TranslationRequest, TranslationResult, DeckTranslationPlan) + adaptateur LLM
(DeckTranslator) + tâche Gradle thin (`translateDeck`). Zéro leak LLM hors
adaptateur (pattern `slider.repository` / `slider.capsule`).

_Dépendances_ :
* `i18n-contracts:0.0.2` (LanguageCatalog.supportedCodes, findByCode) — déjà branché
* `slider.ai.AssistantManager` (resolveModel, OllamaChatModel) — déjà en place
* `slider.translate.TranslatorManager.PromptManager.getTranslatePromptMessage` — réutilisé pour le prompt LLM par langue cible

_Méthode_ : baby-step TDD/BDD — RED → GREEN → REFACTOR. Trois niveaux de tests
par US : unit (value object pur) → functional (GradleTestKit) → cucumber (BDD
end-to-end). English only dans le code, Gherkin, commentaires.

* Unit : value objects purs, zéro dépendance Gradle/LLM. Mock LLM via interface.
