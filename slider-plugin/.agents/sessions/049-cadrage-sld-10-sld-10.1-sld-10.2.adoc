== Cadrage EPIC SLD-10

=== Vision

slider génère des slides AsciiDoc → HTML via Reveal.js, mais n'a aucun modèle
de contenu de slide qui permette d'évaluer le rendu. Les validations Playwright
existantes (LTR/RTL) vérifient la structure globale (titre, slides, bounding
box) mais pas le contenu textuel individuel. SLD-10 crée le domaine DDD
`slider.content` modélisant le contenu d'une slide et des assertions de rendu
pour valider que le texte est dans l'écran, que les notes orateur sont bien
rendues, et que la lisibilité est correcte.

=== Périmètre

- `SlideContent` (aggregate root : titre, sous-titres, paragraphes, listes, notes orateur)
- `TextBlock` (value object : texte, position estimée, bounding box)
- `SlideLayout` (value object : dimensions viewport, marges, font sizes)
- `OverflowDetector` (domain service : prédit si un TextBlock dépasse le viewport)
- `AsciidocContentParser` (parseur .adoc → SlideContent, étend `AsciidocSpeakerNoteParser`)
- Assertions Playwright (pures) : TextOverflow, NotesRendering, FontSize, Contrast

=== Patterns de référence

- `slider.rtl.RtlSlideAssertion` (object pur, `assertAll(data) → Result`, codes P0/P1 enum)
- `slider.capsule.AsciidocSpeakerNoteParser` (object pur, parseur `.adoc` ligne par ligne)

== US SLD-10.1 — TextBlock + SlideLayout

Baby-step TDD : RED (compilation échoue) → GREEN (10 + 10 = 20 tests PASS).

=== `TextBlock` (value object pur)

- Champs : `text`, `x`, `y`, `width`, `height`
- Validation : `require(text.isNotBlank())`, `require(width >= 0.0)`, `require(height >= 0.0)`
- Dérivés : `rightEdge` (`x + width`), `bottomEdge` (`y + height`), `characterCount` (`text.length`)
- Pattern : `slider.capsule.SlideSegment` (value object, `init { require(...) }`)

=== `SlideLayout` (value object pur)

- Champs : `viewportWidth`, `viewportHeight`, `marginX`, `marginY`, `titleFontSize`, `bodyFontSize`
- Validation : `require(viewportWidth > 0)`, `require(viewportHeight > 0)`, `require(marginX >= 0.0)`,
  `require(marginY >= 0.0)`, `require(titleFontSize > 0.0)`, `require(bodyFontSize > 0.0)`
- Dérivés : `contentWidth` (`viewportWidth - 2*marginX`), `contentHeight` (`viewportHeight - 2*marginY`)

== US SLD-10.2 — OverflowDetector

Baby-step TDD : RED (compilation échoue) → GREEN (12 tests PASS).

=== `OverflowReason` (enum)

- `HORIZONTAL_OVERFLOW` (P0 — block croise marge gauche ou dépasse viewport droite)
- `VERTICAL_OVERFLOW` (P0 — block croise marge haut ou dépasse viewport bas)
- `ESTIMATED_TEXT_TOO_LONG` (P1 — largeur estimée texte dépasse contentWidth)

=== `OverflowResult` (sealed interface)

- `Fits` (data object) — le block tient dans le content area
- `Overflow(reason, message)` (data class) — le block dépasse pour une raison donnée

=== `OverflowDetector` (domain service, object pur)

- `detect(block, layout): OverflowResult` — vérifie 3 conditions ordonnées :
  1. horizontalOverflow (marges gauche/droite viewport)
  2. verticalOverflow (marges haut/bas viewport)
  3. estimatedTextOverflow (largeur estimée `chars × bodyFontSize × 0.5` > contentWidth)
- `overflows(block, layout): Boolean` — helper
- Average glyph width ratio : `0.5` (conservatif pour polices proportionnelles Latin)
