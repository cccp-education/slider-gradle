= Session 023 — slider-gradle — Investigation Playwright Gem JRuby
:session: 023
:date: 2026-07-09

== Mission

Investigation des 2 tests Playwright échouant depuis la session 006 :
`RtlPlaywrightFunctionalTest` + `SliderPlaywrightE2eTest` — `LoadError: no such
file to load -- asciidoctor-revealjs` dans JRuby isolé du GradleRunner.

== Diagnostic

Root cause : `GradleRunner.create()` crée un Gradle user home isolé dans `/tmp`.
JRuby ne trouve pas la gem `asciidoctor-revealjs` dans cet environnement vierge.
La gem est bien présente dans `~/.gradle/caches/modules-2/files-2.1/rubygems/asciidoctor-revealjs/5.2.0/`
mais le GradleRunner ne partage pas ce cache.

== Approches explorées

| Approche | Résultat |
| `withGradleUserHomeDir(File)` | N'existe pas dans Gradle 9.6.1 GradleRunner API (vérifié via javap) |
| `GRADLE_USER_HOME` env var via `withEnvironment()` | Non respectée par GradleRunner — le temp dir est toujours utilisé |
| `--offline` flag | Bloque la résolution mavenLocal du plugin slider (nécessaire pour le build) |
| `asciidoctorGemsPrepare` avant `asciidoctorRevealJs` | La gem est dans `~/.gradle` réel, pas dans le temp dir — même erreur |
| `gradleTestKit()` dans testImplementation | Compile mais `withGradleUserHomeDir` toujours absent de l'API |

== Conclusion

Les 2 tests Playwright ne sont pas fixables sans modification de l'API GradleRunner
(ajout de `withGradleUserHomeDir`). Solutions possibles :

. Installer `asciidoctor-revealjs` en gem système (hors JRuby) — `gem install asciidoctor-revealjs`
. Attendre que GradleRunner expose `withGradleUserHomeDir` (feature request Gradle)
. Marquer ces tests comme `@Disabled` avec raison documentée

Ces échecs sont préexistants (session 006 passait car le cache temp était chaud
d'une exécution précédente). Aucune régression introduite.
