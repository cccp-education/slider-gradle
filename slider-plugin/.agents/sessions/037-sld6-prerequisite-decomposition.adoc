== Objectif

SLD-6.3 — Extraction `Prerequisites` → `slider.prerequisite` (nouveau domaine
DDD). `JavaVersionGuard` (value object + `requireJava23()` + `requireJava23FromMajor()`).
Extraction de la logique pure (parse version + guard) hors du contexte Gradle.
`SliderManager.Prerequisites` devient thin adapter qui passe
`JavaVersion.current().majorVersion` au guard.

== Livré

=== Domaine DDD `slider.prerequisite` (nouveau, 1 fichier, ~45 lignes)

- `JavaVersionGuard.kt` (45 lignes) — object pur encapsulant la garde de version
  Java. Zéro dépendance Gradle, zéro JVM introspection. Le caller fournit la
  version majeure (Int ou String).
  - `requireJava23(currentMajor: Int)` — validation pure, `require(...) >= 23`
    avec message clair `education.cccp.slider requires Java 23+. Current: Java N`.
  - `requireJava23FromMajor(majorVersionString: String)` — parse la String
    (issue de `JavaVersion.current().majorVersion`) et délègue à `requireJava23`.
    Rejette les strings blank/non-numériques avec `IllegalArgumentException`.

=== `SliderManager.Prerequisites` → thin adapter

Avant (13 lignes de logique inline) :
----
object Prerequisites {
    internal fun checkJavaVersion() = JavaVersion
        .current().majorVersion.toInt().run {
            require(JavaVersion.current().majorVersion.toInt() >= 23) {
                "education.cccp.slider requires Java 23+. Current: Java $this"
            }
        }
}
----

Après (thin adapter, 11 lignes) :
----
object Prerequisites {
    internal fun checkJavaVersion() =
        slider.prerequisite.JavaVersionGuard.requireJava23FromMajor(
            JavaVersion.current().majorVersion,
        )
}
----

Le `SliderPlugin.apply()` continue d'appeler `Prerequisites.checkJavaVersion()`
en première étape — signature publique préservée, zéro régression.
