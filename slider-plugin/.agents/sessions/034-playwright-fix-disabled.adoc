:session: 034

== Mission

Fixer les 2 tests Playwright `@Disabled` depuis la session 023 :
`SliderPlaywrightE2eTest` + `RtlPlaywrightFunctionalTest` — root cause :
`GradleRunner` crée un Gradle user home isolé dans `/tmp` où JRuby ne trouve
pas la gem `asciidoctor-revealjs` (LoadError).

== Solution

Découplage architecturel : séparer la génération HTML (GradleRunner → JRuby
isolé, non fixable sans API `withGradleUserHomeDir` absente de Gradle 9.6.1)
de la validation visuelle Playwright (chargement d'un HTML pré-généré).

Approche DDD :
- Les HTML fixtures sont pré-générés par le build racine `slider-gradle` (vrai
  Gradle home, gem JRuby présente) via une nouvelle tâche `generatePlaywrightFixtures`.
- Les tests Playwright chargent ces fixtures via `python3 -m http.server` (remplacement
  `npx serve` qui faisait une 301 intempestive) + Playwright-jvm headless Chromium.
- Pas de GradleRunner → pas de JRuby isolé → pas de LoadError.

Tâches Gradle créées (build.gradle.kts racine) :
- `copyPlaywrightLtrFixture` (Copy) — copie `build/docs/asciidocRevealJs/` → `build/playwright-fixtures/ltr/`
- `generateRtlFixture` (Exec) — re-lance `asciidoctorRevealJs -Planguage=ar` puis copie → `build/playwright-fixtures/rtl/`
- `generatePlaywrightFixtures` (aggregation) — orchestre les 2 ci-dessus

Fixtures :
- LTR : `capsule-feed-demo-en-deck.html` (rtl: false)
- RTL : `capsule-feed-demo-ar-deck.html` (rtl: true, nécessite `-Planguage=ar`)

Séquençage : `copyPlaywrightLtrFixture` s'exécute avant `generateRtlFixture`
(`mustRunAfter`) car le build RTL écrase le output `asciidocRevealJs/` partagé.
