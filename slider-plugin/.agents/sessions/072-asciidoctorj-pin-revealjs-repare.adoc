== Contexte

Reprise slider à la demande pilote. Le PROMPT_REPRISE 071 listait une
*unique dette locale actionnable sans coût externe* : le rendu
`asciidoctorRevealJs` Gradle cassé par un conflit de gems JRuby
(`jar-dependencies 0.5.4 vs 0.4.1`, préexistant S-023/S-034). Cette dette
bloquait tout dogfooding HTML automatisé et forçait un contournement Ruby
système (`gem install asciidoctor asciidoctor-revealjs`) au dogfooding
capsule S-226.

== Diagnostic — la cause racine (dépassant le symptôme « gems »)

L'analyse initiale S-023/S-034 attribuait l'échec à un *JRuby isolé du
GradleRunner* (tests Playwright). La reproduction réelle sur le build racine
révèle **deux causes distinctes** :

. **Conflit JRuby double sur le worker `OUT_OF_PROCESS`** (cause de l'échec
   `asciidoctorRevealJs`) : la tâche résout le défaut asciidoctor-gradle
   `asciidoctorj:3.0.0` → `jruby-complete:9.4.8.0` (gem `jar-dependencies`
   **0.4.1**), tandis que le classpath du plugin (via `workspace-bom` /
   `codebase-plugin`) contraint `asciidoctorj:3.0.1` →
   `jruby-stdlib:9.4.14.0` (`jar-dependencies` **0.5.4**). Les deux JRuby
   atterrissent sur le même classpath ; JRuby active 0.4.1 puis échoue à
   activer 0.5.4 → `Gem::LoadError: can't activate jar-dependencies-0.5.4,
   already activated jar-dependencies-0.4.1`. `asciidoctorGemsPrepare` avorte,
   le jar de gems reste **vide** (261 octets, META-INF seul), et la tâche
   échoue en `LoadError: no such file to load -- asciidoctor`.
. **JRuby isolé du GradleRunner** (cause des 3 tests Playwright) : distincte,
   déjà traitée par l'architecture fixtures S-034. Les fixtures n'étaient
   simplement *jamais générées* parce que la cause 1 cassait
   `asciidoctorRevealJs` → `generatePlaywrightFixtures`.

== Décisions

. *Fix dans le plugin, pas dans le build consommateur* — le pin est une
   propriété du plugin distribué ; le contournement `build.gradle.kts racine`
   (testé en premier) n'aurait corrigé qu'un consommateur.
. *Pin aligné sur le classpath du plugin (3.0.1)* — la version est celle que
   le plugin porte déjà ; le plugin unifie le runtime au lieu d'imposer la
   sienne au consommateur.
. *Test décisif unique* — le test « single JRuby » passait sans le pin
   (non discriminant) → retiré pour ne pas laisser un faux positif vert.
. *Bump, pas réutilisation* — 0.0.19 Central est immuable ; le correctif
   mérite 0.0.20.
