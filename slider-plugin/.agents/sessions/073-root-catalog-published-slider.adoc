= Session 073 — Racine alignée sur la version publiée (`slider 0.0.20 → 0.0.19`)
:session: 073
:date: 2026-10-12
:type: fix (cross-borough)

== Contexte / symptôme

Le job **cross-borough** `runAllTests` de MEMPHIS (`workspace-bom`) exécute
`./gradlew check` dans la racine consommatrice de slider et échoue :

----
Plugin [id: 'education.cccp.slider', version: '0.0.20'] was not found in any of the
following sources: Plugin Repositories (could not resolve plugin artifact
'education.cccp.slider:education.cccp.slider.gradle.plugin:0.0.20')
----

== Cause racine

La **racine consommatrice** (`slider-gradle/gradle/libs.versions.toml`) épinglait
`slider = "0.0.20"`, or **`slider-plugin 0.0.20` n'est pas publié** : Maven Central
ne porte que **0.0.18** et **0.0.19** (S-072 a bumpé le plugin à 0.0.20 *localement*,
sans publication). Le catalogue workspace MEMPHIS épingle `slider-plugin = 0.0.19`
(source de vérité publiée). Une racine consommatrice (pattern article 0124) doit
référencer une version **publiée**.

== Correctif

* `slider-gradle/gradle/libs.versions.toml` : `slider = "0.0.20"` → **`"0.0.19"`**
  (aligné MEMPHIS `workspace-catalog`). La version 0.0.20 reste la version *de dev*
  du plugin (EPIC PUB 0.0.20 candidat, hors périmètre).

== Vérification

* `./gradlew help` depuis la racine : **exit 0** (JDK 25) — résolution du plugin OK
  (échouait à la configuration avec 0.0.20).
* Le job cross-borough MEMPHIS utilise désormais **JDK 25** (fix MEMPHIS S-284) ;
  les artefacts cccp exigent JVM 25.

== Note

Aucune modification du plugin slider lui-même (le plugin reste à 0.0.20 en dev).
Seule la racine consommatrice est réalignée sur la version publiée.

_Score : 8/10._
