== Livrables

=== Domaine `slider.content` (3 nouveaux fichiers)

. `ContentAssertionCode.kt` (22l) — enum 4 codes :
  - P0_OVERFLOW — un paragraphe ou le titre déborde l'aire de contenu
  - P0_MISSING_NOTES — la slide n'a pas de note orateur
  - P1_FONT_SIZE — body font size < 14 CSS px (MIN_BODY_FONT_SIZE)
  - P1_CONTRAST — ratio title/body < 1.25 (MIN_TITLE_BODY_RATIO)

. `ContentAssertionResult.kt` (41l) — sealed interface `Passed` (data
  object) + `Failed` (data class, `failures: List<ContentAssertionFailure>`,
  `init { require(failures.isNotEmpty()) }`, `failureCodes()`).
  `ContentAssertionFailure` (data class : code, message, slideRef).

. `ContentSlideAssertion.kt` (88l) — object `assertAll(content, layout):
  ContentAssertionResult`. Délègue l'estimation d'overflow à
  `OverflowDetector` via `TextBlock` synthétiques (title + chaque
  paragraphe). Constantes publiques `MIN_BODY_FONT_SIZE = 14.0`,
  `MIN_TITLE_BODY_RATIO = 1.25`.

=== Tests (11 nouveaux unitaires)

. `ContentSlideAssertionTest.kt` — 11 tests :
  - slide complète avec note → Passed
  - P0_OVERFLOW (paragraphe 200 chars)
  - P0_MISSING_NOTES (slide sans note)
  - P1_FONT_SIZE (body 8px < 14)
  - P1_CONTRAST (ratio 22/20 = 1.1 < 1.25)
  - title-only sans note → exactement P0_MISSING_NOTES
  - tous échecs signalés d'un coup (4 codes)
  - slideRef = titre de la slide sur chaque failure
  - message contient le code name
  - Passed est un data object
  - Failed expose la liste failures
