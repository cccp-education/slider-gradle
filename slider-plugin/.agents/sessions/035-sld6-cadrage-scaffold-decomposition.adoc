== Contexte

`SliderManager.kt` est un god-object de 968 lignes contenant 9 nested objects
(Configuration, Prerequisites, Scaffold, Repositories, Plugins, Dependencies,
Extensions, Tasks, Git). Alors que les 6 domaines métier DDD ont déjà été
extraits proprement (`slider.repository`, `slider.capsule`, `slider.rtl`,
`slider.i18n`, `slider.translate`, `slider.translation`), le `SliderManager`
reste le point d'agglomération résiduel — il mélange Gradle plumbing, scaffold,
configuration, enregistrement de tâches et adaptateur Git.

SLD-6 applique le même pattern DDD déjà utilisé pour `repository`/`capsule`/
`translation` au `SliderManager` lui-même : extraire chaque responsabilité dans
un domaine dédié, baby-step TDD/BDD 3 niveaux, jusqu'à ce que `SliderManager`
devienne un thin orchestrator (< 100 lignes).
