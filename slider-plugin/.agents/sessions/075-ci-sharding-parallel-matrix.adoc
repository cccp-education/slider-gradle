== Contexte / mission

Le repo slider n'avait **aucun workflow de test** (`.github/workflows/` ne contenait
que `generate_deck.yml`, `readme_plantuml.yml`, `readme_truth.yml`, `website.yml`,
pré-existants, certains rouges à 0 s — hors périmètre). Mission : éclater les tests en
**shards parallèles** dans GitHub Actions, exactement comme `capsule-gradle`
(S-198). Chaque shard tourne sur **sa propre machine** (1 JVM/shard), la couverture
d'origine (`cucumberTest` agrégé = 25 features, `functionalTest` = 9 classes,
`test` unit) est **intégralement préservée**.

Chaque runner porte `@SelectClasspathResource("features/<file>")` (répétable),
`@ConfigurationParameter(FEATURES_PROPERTY_NAME, ...)` (leçon S-198 : le moteur
Cucumber exige `cucumber.features`), `GLUE_PROPERTY_NAME = "slider.steps"`, et le
filtre agrégé **`not @wip and not @integration`** — le sharding exécute **exactement**
ce que `cucumberTest` exécutait.

*Aucun shard n'a besoin de ffmpeg ni de Chromium* : toutes les features slider sont
**pure-domaine** (contrairement à capsule). Les features 10/21/24 manipulent des DTO
snapshot (RTL / contenu / commandes Playwright) — elles n'ouvrent **jamais** un
navigateur.

== Garde d'exhaustivité (§ anti « test fantôme » S-269)

`slider-plugin/src/test/kotlin/slider/ci/SliderCucumberShardCoverageTest.kt`
(4 tests, exécutés dans le job `unit`) — lecture pure des sources, sans modèle Gradle :

. les shards forment une **partition exhaustive et disjointe** des 25 features, et
  **chaque** shard préserve le filtre agrégé (`not @wip` + `not @integration`) ;
. chaque runner de shard est une **tâche Gradle** (`CucumberTaskSpec`) **et** est
  **invoquée par `full-tests.yml`** (égalité ensembliste des noms de tâches) ;
. les shards `functionalTest` forment une partition exhaustive/disjointe des 9 classes ;
. le job unitaire exécute bien `./gradlew test`.

Un runner non enregistré ou une feature orpheline fait échouer la gate — plus de test
silencieusement non exécuté.

`slider-plugin/build.gradle.kts` : `import build.CucumberTaskSpec` +

== Correctifs nécessaires à la CI verte

. *`settings.gradle.kts` — fallback nmcp* : `centralPortal.username/password`
  `?: error(...)` → **`?: \"\"`**. Un runner CI n'a pas de
  `~/.gradle/gradle.properties` ; l'`error` cassait **toute** la configuration
  (`test`, `compileKotlin`…) — pattern codebase S-269 / dashboard S-217.
. *3 tests Playwright visuels (unit) — auto-skip* : les fixtures HTML Reveal.js sont
  produites par la **racine consommatrice** (`generatePlaywrightFixtures`), qui épingle
  le plugin **publié** (`slider = 0.0.19`, **sans** le fix AsciidoctorJ S-072). En CI
  elles sont absentes → `PlaywrightFixtureSupport.requireFixture(...)` (assumeTrue)
  **skippe** proprement au lieu d'échouer (3 skipped). `closeBrowser()` rendu
  null-safe. Doctrine = `assumeTrue(isOllamaReady(port))`.
. *`SlideDeploymentPipelineIntegrationTest`* : `git.log()` (suivi HEAD) levait
  `NoHeadException` en CI — le HEAD du bare remote reste sur le défaut JGit (`master`)
  car `init.defaultBranch=main` n'existe que dans la config git locale. **Fix
  déterministe** : logger la ref **explicite** `refs/heads/main`.
. *Image pgvector du shard core* : la feature 2 (`proposeDeckContext`, RAG) démarre un
   conteneur pgvector via docker-java ; le `pullImageCmd` du plugin est peu fiable en
   CI (`No such image: pgvector/pgvector:pg17`). **Pré-pull** `docker pull
   pgvector/pgvector:pg17` dans le job `core` (flag matrice `pgvector`), mirror codebase
   (`docker pull ollama/ollama`).
