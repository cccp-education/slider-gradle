== Vision SLD-10 — Slide Content Model & Rendering Validation

=== Problématique

Aujourd'hui slider génère des slides AsciiDoc → HTML via Reveal.js, mais n'a
**aucun modèle de contenu de slide** qui permette d'évaluer le rendu. Les
validations Playwright existantes (LTR/RTL) vérifient la structure globale
(titre, slides, bounding box) mais pas le contenu textuel individuel.

=== Périmètre envisagé

. **SlideContentModel** — domaine DDD `slider.content` modélisant :
  * `SlideContent` (aggregate : titre, sous-titres, paragraphes, listes, notes)
  * `TextBlock` (value object : texte, position, bounding box estimée)
  * `SlideLayout` (value object : dimensions viewport, marges, font sizes)
  * `OverflowDetector` (domain service : prédit si le texte dépasse l'écran)
  * `AsciidocContentParser` (parseur .adoc → SlideContent, incluant `[NOTE.speaker]`)

. **Playwright Rendering Assertions** — nouvelles assertions visuelles :
  * `TextOverflowAssertion` — vérifie que le texte est dans le viewport
  * `NotesRenderingAssertion` — vérifie que les notes orateur sont bien rendues
  * `FontSizeAssertion` — vérifie la lisibilité (taille police > seuil)
  * `ContrastAssertion` — vérifie le contraste texte/fond

. **Tests 3 niveaux** (baby-step DDD/TDD/BDD) :
  * Unit : SlideContentModel pur, OverflowDetector mocké
  * Functional : GradleTestKit + Playwright-jvm assertions
  * Cucumber : BDD end-to-end content validation

=== Dépendances

- `slider.rtl.RtlSlideAssertion` — pattern de référence pour les assertions
