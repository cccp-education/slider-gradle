== Livré

=== Domaine DDD `slider.config` (nouveau, 3 fichiers, ~110 lignes)

- `ConfigPath.kt` (21 lignes) — value object `@JvmInline value class` encapsulant
  le path du fichier de configuration. Validation non-blanc, résolution relative
  vs absolue contre base dir. Pure — zéro Gradle, zéro filesystem.
- `YamlMapperFactory.kt` (34 lignes) — factory du `ObjectMapper` partagé
  (YAMLFactory + Kotlin + Arrow + WRITE_DATES_AS_TIMESTAMPS disabled). Remplace
  l'extension property `SliderManager.Configuration.yamlMapper`. Centralise la
  configuration Jackson pour tout le borough.
- `SlidesConfigLoader.kt` (70 lignes) — domain service. `load(File, ObjectMapper)`
  + `load(configPath, baseDir, mapper)` + `emptyConfiguration()` fallback. Remplace
  `SliderManager.Configuration.readSlidesConfigurationFile`. Try/catch conservé
  pour préserver le contrat historique (build continue en mode dégradé).

=== SliderManager.Configuration → thin adapter

- `Project.localConf` : `properties[CONFIG_PATH_KEY]` → `findProperty(CONFIG_PATH_KEY)`
  (API Gradle stable, zéro warning). Délègue à `SlidesConfigLoader.load(...)`.
- `yamlMapper` : délègue à `YamlMapperFactory.create()`.
- `readSlidesConfigurationFile(configPath)` : délègue à `SlidesConfigLoader.load(File, mapper)`.
- `registerPublishSlidesTask` (ligne 638) : re-désérialisation `YAMLMapper().readValue`
  supprimée — réutilise `localConf` (thin adapter). Fix second site deprecation.
