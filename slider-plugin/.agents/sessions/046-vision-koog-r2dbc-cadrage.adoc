== Audit PicoContainer (Decision 001)

- **Zéro implémentation** : aucun import `org.picocontainer` dans tout le
  workspace (production ou test).
- **Absent de tous les catalogues** : aucun `libs.versions.toml` ne déclare
  `org.picocontainer:pico-container`.
- **Confusion levée** : `io.cucumber:cucumber-picocontainer` (7.34.3) est déclaré
  et consommé dans 15 boroughs (dont slider, via `libs.bundles.cucumber`) — c'est
  le module officiel Cucumber d'injection des `World`/`Steps` par scénario (BDD
  test), **pas** une DI de production.
- **Décision** : rejet assumé de PicoContainer comme conteneur DI de production.
  La DI native Gradle (`@Inject`, `BuildService`, `Provider<T>`, `Property<T>`)
  couvre le besoin (injection par constructeur, cycle de vie Gradle, zéro
  dépendance, isolation classloader). PicoContainer = projet sans mainteneur actif
  (dernière release stable ~2018). Statut valable jusqu'à réévaluation (critères
  listés dans la décision).
