= Session 031 — Alliance i18n : TranslationServiceAdapter
:date: 2026-07-31
:type: feat
:score: 9/10

== Contexte

Slider utilisait `LanguageCatalog` du BOM pour la validation des langues mais
avait son propre modèle de domaine incompatible pour la traduction :
`slider.translation.TranslationRequest`, `slider.translation.TranslationResult`,
`slider.translation.LanguageModelAdapter`. Aucun pont vers le contrat N0
`TranslationService` du BOM.

== Actions

. Création de `TranslationServiceAdapter.kt` dans `slider.translation` :
  - Implémente `contracts.i18n.TranslationService`
  - Wrappe `LanguageModelAdapter` (port DDD hexagonal existant)
  - Prend un `DeckContext` au constructeur pour le contexte LLM
  - Délégue `translate()` → `modelAdapter.translate(deckContext, adocContent, source, target)`
  - Mapping : `String?` → `TranslationResult.Success` / `TranslationResult.Failure`

. Vérification : `./gradlew :slider:compileKotlin` BUILD SUCCESSFUL

== Impact

- +1 fichier (additif, zéro fichier existant modifié)
- Slider expose maintenant un `TranslationService` consommable par l'alliance
- Le `LanguageModelAdapter` (port DDD) reste intact — l'adaptateur est un pont, pas un remplacement
- Fait partie de l'alliance i18n cross-borough (bakery + slider + plantuml + document)
