== Architecture

`DeckPipelineKoogSteps` construit des fakes en mémoire implémentant les ports
`DeckLlm` et `DeckPromptBuilder` (mirroring `DeckPipelineGraphTest` 8.3b +
`DeckTranslationSteps` SLD-5). Le graphe `DeckPipelineGraph` est exercé via
`execute(initialState)` ; les scénarios assertent sur la sealed `DeckState`
retournée (stage, deckAdoc, deckContextJson, error, contextValid) et sur les
effets de bord enregistrés par le `RecordingPromptBuilder` (états capturés à
chaque appel → vérification des transitions de stage).

Couverture BDD alignée sur les 17 unit tests de 8.3b et les 7 functional
tests de 8.3c — les 12 scénarios recoupent les 3 nœuds, les 2 edges
conditionnels, et les 3 failure modes (validator, propose LLM, generate LLM).

== Décisions

* **Pure BDD** — baby-step 8.3d n'ajoute aucune logique métier (déjà livrée
  par 8.3a/b/c), uniquement la couverture BDD end-to-end. Pattern aligné sur
  SLD-10.6 (S-054) où la logique était déjà en place et la feature Cucumber
  validait les objects purs.
* **Fakes privés dans les steps** — `RecordingPromptBuilder` et
  `FakeDeckLlm` sont des classes privées de `DeckPipelineKoogSteps` (pas de
  sharing avec `DeckPipelineGraphTest` qui a ses propres fakes). Évite le
  couplage test↔BDD et garde chaque classe auto-contenue (pattern
  `DeckTranslationSteps.StubAdapter`).
* **Tags `@pipeline @koog`** — cohérents avec les tags `@content @validation`
  de S-054 et `@i18n` de S-057. Pas d'exclusion dans `CucumberTestRunner`
  (filtre `not @wip and not @integration` — 8.3d n'est ni WIP ni integration
  puisque le LLM est mocké).
