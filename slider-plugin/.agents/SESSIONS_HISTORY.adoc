server (`python3 -m http.server` — remplace `npx serve` qui faisait une 301
intempestive). Les 2 tests réécrits chargent les fixtures pré-générées sans

JRuby ne trouve pas la gem `asciidoctor-revealjs` dans cet environnement vierge.
La gem est bien présente dans `~/.gradle/caches/modules-2/files-2.1/rubygems/asciidoctor-revealjs/5.2.0/`
mais le GradleRunner ne partage pas ce cache.

5 approches testées :
- `withGradleUserHomeDir(File)` — n'existe pas dans Gradle 9.6.1 GradleRunner API (vérifié via javap)
- `GRADLE_USER_HOME` env var via `withEnvironment()` — non respectée par GradleRunner
- `--offline` flag — bloque la résolution mavenLocal du plugin slider
- `asciidoctorGemsPrepare` avant `asciidoctorRevealJs` — gem dans ~/.gradle réel, pas temp dir
- `gradleTestKit()` dans testImplementation — compile mais méthode toujours absente

Non fixable sans modification de l'API GradleRunner. Solutions : gem install
asciidoctor-revealjs système-wide, feature request GradleRunner.withGradleUserHomeDir,
ou @Disabled avec raison documentée.

Aucun fichier modifié — investigation pure, code reverté à l'état original.
